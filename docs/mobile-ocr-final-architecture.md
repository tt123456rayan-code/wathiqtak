# معمارية OCR المحلي النهائية للهواتف

## لماذا Tesseract غير كافٍ

Tesseract مناسب كتجربة Web أولية، لكنه ليس حلًا أساسيًا للكتب الحكومية العربية على الهواتف الضعيفة والمتوسطة. أداؤه يتأثر كثيرًا بجودة الصورة، وملفات اللغة العربية ثقيلة نسبيًا، وسرعة المعالجة داخل المتصفح محدودة، كما أن التعامل مع الجداول والأختام والترويسات الرسمية ليس ثابتًا.

## لماذا Web OCR ضعيف للكتب الحكومية العربية

نسخة الويب تعمل داخل قيود المتصفح: ذاكرة أقل، workers محدودة، صعوبة ضبط نماذج مخصصة، وتحميل ملفات اللغة أول مرة. الكتب الحكومية غالبًا تحتوي ترويسات، أرقام، أختام، خطوط عربية مختلفة، جداول، وتباين ضعيف. لذلك Web OCR يبقى خيارًا تجريبيًا للعرض وليس المسار النهائي.

## لماذا ML Kit ليس خيارًا عربيًا أساسيًا

ML Kit قوي في سيناريوهات كثيرة، لكنه ليس المسار الأساسي هنا لأن دعم العربية في الوثائق الرسمية الطويلة والجداول ليس مضمونًا كحل نهائي، ولأنه يربط جودة المنتج بقدرات مزود محدد. المطلوب هو OCR محلي يمكن التحكم بنماذجه وأدائه وميزانيته على الجهاز.

## لماذا PaddleOCR Mobile هو المسار الأفضل

PaddleOCR Mobile عبر Paddle Lite أو ONNX Runtime Mobile يسمح بتشغيل نماذج OCR محلية على Android، مع إمكانية اختيار نموذج خفيف، ضبط pre-processing، تقسيم الصورة إلى مناطق، وتحسين الأداء حسب قوة الجهاز. هذا يناسب هدف وثيقتك: لا Cloud API، لا أسرار، ولا إرسال صور خارج الجهاز.

## كيف يعمل التطبيق محليًا

1. يلتقط المستخدم صورة الكتاب أو يرفعها.
2. يتم ضغط الصورة ومعالجتها داخل الجهاز.
3. يتم اختيار وضع OCR حسب قوة الجهاز.
4. Native OCR يستخرج النص داخل Android.
5. يرسل النص إلى واجهة React.
6. `analysisEngine` يحلل النص محليًا ويولد الخطوات والرد.

لا يتم رفع الصورة أو النص لأي خادم.

## دعم الأجهزة

- الأجهزة الضعيفة: صورة أصغر، تقسيم إلى مناطق، تصحيح يدوي إلزامي.
- الأجهزة المتوسطة: توازن بين السرعة والدقة، تقسيم ذكي، تحليل تلقائي بعد OCR.
- الأجهزة القوية: pipeline كامل، deskew، عرض أعلى للصورة، دقة أعلى.

## Lite / Balanced / Pro

- Lite: للهواتف الضعيفة. `maxImageWidth = 1000`، regions enabled، manual correction required.
- Balanced: لمعظم الهواتف. `maxImageWidth = 1400`، regions enabled، auto analysis.
- Pro: للهواتف القوية. `maxImageWidth = 1800`، full pipeline.

## بقاء التحليل محليًا

حتى بعد إضافة Native PaddleOCR، يبقى تحليل الخطاب في `src/lib/analysisEngine.ts`. OCR مسؤوليته استخراج النص فقط، أما تحديد نوع الخطاب والمهلة والخطورة والرد الرسمي فيبقى rule-based ومحليًا داخل التطبيق.
